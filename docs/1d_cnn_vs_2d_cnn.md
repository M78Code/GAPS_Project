# なぜ1D CNNを使うのか：波形データにおける1D CNN vs 2D CNN

## 結論

**波形データ（時系列）には1D CNNが正しい選択。2D CNNは不適切。**

---

## データ形状の本質

今回のデータ形状は `[2, 1024]` だが、これは「画像」ではない。

```
CH0: [点1, 点2, 点3, ..., 点1024]  ← 時系列（時間軸）
CH1: [点1, 点2, 点3, ..., 点1024]  ← 時系列（時間軸）
```

- **1024の方向**：時間軸（採様点）→ 隣接する点に物理的な意味がある
- **2の方向**：CH0とCH1という2つの独立したセンサー → 空間的な隣接関係はない

---

## 2D CNNが不適切な理由

2D CNNは「空間的な2次元構造」を持つデータに適している。

```
画像の例：[高さ, 幅]
→ 縦方向にも横方向にも「隣り合うピクセル」に意味がある
→ 2次元の畳み込みカーネルが空間パターンを学習できる
```

今回のデータでCH0とCH1の間（2の方向）に畳み込みをかけることは**物理的に無意味**。
CH0とCH1は異なる位置に置かれた独立したセンサーであり、「空間的に隣り合っている」わけではない。

---

## 1D CNNが適切な理由

PyTorchにおける1D CNNの入力フォーマット：

```
[batch, in_channels, length]
= [64,      2,        1024]
```

ここでの `in_channels=2` は、**画像CNNにおけるRGBの3チャンネルと全く同じ概念**。

```
画像（RGB）：  [batch, 3,  H,    W  ] → Conv2dがH×Wの空間上をスライド
波形（2ch）：  [batch, 2, 1024     ] → Conv1dが時間軸上をスライド
```

畳み込みカーネルは**時間軸方向にスライドしながら、CH0とCH1を同時に参照**し、
2チャンネル間の関係を自動的に学習する。

---

## まとめ

| | 1D CNN | 2D CNN |
|---|---|---|
| 適したデータ | 時系列・波形 | 画像・スペクトログラム |
| 畳み込み方向 | 時間軸のみ | 時間軸 × 周波数／空間軸 |
| 複数チャンネル | `in_channels` として自然にサポート | 2次元の空間構造が必要 |
| 今回のデータ | **正しい選択** | 不適切（2の方向に空間的意味がない） |

2チャンネルは「高さ」ではなく `in_channels` として扱う。1D CNNは多チャンネル入力をネイティブにサポートしており、波形データの解析に最適。

---

## 参考：PyTorchでの実装イメージ

```python
import torch.nn as nn

# 入力: [batch, 2, 1024]
conv = nn.Conv1d(in_channels=2, out_channels=32, kernel_size=7)
# カーネルが時間軸上をスライドし、CH0とCH1を同時に見る
# 出力: [batch, 32, 1018]
```
